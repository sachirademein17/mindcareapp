🧠 MindCare AWS Deployment Guide

Complete guide for hosting your Mental Health Platform on AWS

Ubuntu EC2 • PostgreSQL RDS • S3 File Storage

📋 Prerequisites

Before you start, ensure you have:

  • AWS Account with appropriate permissions
  • AWS CLI installed and configured
  • Your MindCare project ready and tested locally
  • Domain name (optional, but recommended)
  • SSH client (PuTTY for Windows, Terminal for Mac/Linux)

🔧 Install AWS CLI

# Windows (PowerShell) msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi # macOS curl "https://awscli.amazonaws.com/AWSCLIV2.pkg" -o "AWSCLIV2.pkg" sudo installer -pkg AWSCLIV2.pkg -target / # Linux curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o "awscliv2.zip" unzip awscliv2.zip sudo ./aws/install

⚙️ Configure AWS CLI

aws configure # Enter your AWS Access Key ID # Enter your AWS Secret Access Key # Default region name: us-east-1 (or your preferred region) # Default output format: json
🗄️ Step 1: RDS PostgreSQL Database Setup

1.1 Create RDS Subnet Group

aws rds create-db-subnet-group \ --db-subnet-group-name mindcare-subnet-group \ --db-subnet-group-description "Subnet group for MindCare RDS" \ --subnet-ids subnet-12345678 subnet-87654321

1.2 Create Security Group for RDS

# Create security group aws ec2 create-security-group \ --group-name mindcare-rds-sg \ --description "Security group for MindCare RDS PostgreSQL" # Add PostgreSQL access rule (will be updated with EC2 security group later) aws ec2 authorize-security-group-ingress \ --group-name mindcare-rds-sg \ --protocol tcp \ --port 5432 \ --cidr 10.0.0.0/16

1.3 Create RDS PostgreSQL Instance

📝 For ORM Users: You only need to create the database instance. Your ORM will handle table creation!
aws rds create-db-instance \ --db-instance-identifier mindcare-db \ --db-instance-class db.t3.micro \ --engine postgres \ --engine-version 15.4 \ --master-username postgres \ --master-user-password "YourSecurePassword123!" \ --allocated-storage 20 \ --storage-type gp2 \ --backup-retention-period 7 \ --storage-encrypted \ --db-name mindcare_production
✅ That's it for database setup! Your ORM will create all tables automatically when you run migrations.
📝 Note: RDS instance creation takes 5-10 minutes. You can continue with other steps while it's being created.

1.4 Get RDS Endpoint

# Get the endpoint once RDS is available aws rds describe-db-instances \ --db-instance-identifier mindcare-db \ --query 'DBInstances[0].Endpoint.Address' \ --output text

Save this endpoint - you'll need it for your backend configuration.

📁 Step 2: S3 Bucket Configuration

2.1 Create S3 Buckets

# Bucket for file uploads (CVs, documents) aws s3 mb s3://mindcare-file-uploads-yourname --region us-east-1 # Bucket for frontend static files aws s3 mb s3://mindcare-frontend-yourname --region us-east-1
⚠️ Important: S3 bucket names must be globally unique. Replace "yourname" with something unique to you.

2.2 Configure File Uploads Bucket

# Enable versioning for file uploads bucket aws s3api put-bucket-versioning \ --bucket mindcare-file-uploads-yourname \ --versioning-configuration Status=Enabled # Set up CORS for file uploads aws s3api put-bucket-cors \ --bucket mindcare-file-uploads-yourname \ --cors-configuration file://cors-config.json

2.3 Create CORS Configuration

Create a file named cors-config.json:

{
    "CORSRules": [
        {
            "AllowedHeaders": ["*"],
            "AllowedMethods": ["GET", "PUT", "POST", "DELETE"],
            "AllowedOrigins": ["*"],
            "ExposeHeaders": ["ETag"],
            "MaxAgeSeconds": 3000
        }
    ]
}

2.4 Configure Frontend Bucket for Static Hosting

# Enable static website hosting aws s3 website s3://mindcare-frontend-yourname \ --index-document index.html \ --error-document index.html # Set bucket policy for public read access aws s3api put-bucket-policy \ --bucket mindcare-frontend-yourname \ --policy file://bucket-policy.json

2.5 Create Bucket Policy

Create a file named bucket-policy.json:

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::mindcare-frontend-yourname/*"
        }
    ]
}

2.6 Create IAM User for S3 Access

# Create IAM user for application S3 access aws iam create-user --user-name mindcare-s3-user # Create access key aws iam create-access-key --user-name mindcare-s3-user # Attach S3 policy aws iam attach-user-policy \ --user-name mindcare-s3-user \ --policy-arn arn:aws:iam::aws:policy/AmazonS3FullAccess
⚠️ Important: Save the Access Key ID and Secret Access Key - you'll need them for your backend configuration.
🖥️ Step 3: EC2 Ubuntu Server Setup

3.1 Create EC2 Key Pair

# Create key pair aws ec2 create-key-pair \ --key-name mindcare-key \ --query 'KeyMaterial' \ --output text > mindcare-key.pem # Set correct permissions chmod 400 mindcare-key.pem

3.2 Create Security Group for EC2

# Create security group aws ec2 create-security-group \ --group-name mindcare-ec2-sg \ --description "Security group for MindCare EC2 instance" # Add SSH access aws ec2 authorize-security-group-ingress \ --group-name mindcare-ec2-sg \ --protocol tcp \ --port 22 \ --cidr 0.0.0.0/0 # Add HTTP access aws ec2 authorize-security-group-ingress \ --group-name mindcare-ec2-sg \ --protocol tcp \ --port 80 \ --cidr 0.0.0.0/0 # Add HTTPS access aws ec2 authorize-security-group-ingress \ --group-name mindcare-ec2-sg \ --protocol tcp \ --port 443 \ --cidr 0.0.0.0/0 # Add Node.js app port aws ec2 authorize-security-group-ingress \ --group-name mindcare-ec2-sg \ --protocol tcp \ --port 5000 \ --cidr 0.0.0.0/0

3.3 Launch EC2 Ubuntu Instance

# Find latest Ubuntu 22.04 LTS AMI aws ec2 describe-images \ --owners 099720109477 \ --filters "Name=name,Values=ubuntu/images/hvm-ssd/ubuntu-jammy-22.04-amd64-server-*" \ --query 'Images | sort_by(@, &CreationDate) | [-1].ImageId' \ --output text # Launch instance aws ec2 run-instances \ --image-id ami-0c02fb55956c7d316 \ --count 1 \ --instance-type t3.medium \ --key-name mindcare-key \ --security-groups mindcare-ec2-sg \ --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=MindCare-Backend}]'

3.4 Get EC2 Instance Public IP

# Get public IP address aws ec2 describe-instances \ --filters "Name=tag:Name,Values=MindCare-Backend" \ --query 'Reservations[0].Instances[0].PublicIpAddress' \ --output text

Save this IP address - you'll use it to connect to your server.

3.5 Connect to EC2 Instance

# Connect via SSH ssh -i mindcare-key.pem ubuntu@YOUR_EC2_PUBLIC_IP

3.6 Install Dependencies on Ubuntu Server

# Update system sudo apt update && sudo apt upgrade -y # Install Node.js 18 curl -fsSL https://deb.nodesource.com/setup_18.x | sudo -E bash - sudo apt-get install -y nodejs # Install PM2 process manager sudo npm install -g pm2 # Install Nginx sudo apt install -y nginx # Install PostgreSQL client sudo apt install -y postgresql-client # Install Git sudo apt install -y git # Install unzip sudo apt install -y unzip # Create application directory sudo mkdir -p /var/www/mindcare sudo chown ubuntu:ubuntu /var/www/mindcare

3.7 Configure Nginx

# Create Nginx configuration sudo nano /etc/nginx/sites-available/mindcare

Add this Nginx configuration:

server {
    listen 80;
    server_name your-domain.com www.your-domain.com;

    location / {
        proxy_pass http://localhost:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
    }
}
# Enable the site sudo ln -s /etc/nginx/sites-available/mindcare /etc/nginx/sites-enabled/ sudo rm /etc/nginx/sites-enabled/default # Test and reload Nginx sudo nginx -t sudo systemctl reload nginx sudo systemctl enable nginx

4.4 Update Backend Code for S3 Integration

Ensure your backend is configured to use S3 for file uploads. Update your upload middleware:

// Example S3 upload configuration
const AWS = require('aws-sdk');
const multer = require('multer');
const multerS3 = require('multer-s3');

const s3 = new AWS.S3({
    accessKeyId: process.env.AWS_ACCESS_KEY_ID,
    secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY,
    region: process.env.AWS_REGION
});

const upload = multer({
    storage: multerS3({
        s3: s3,
        bucket: process.env.AWS_S3_BUCKET,
        metadata: function (req, file, cb) {
            cb(null, {fieldName: file.fieldname});
        },
        key: function (req, file, cb) {
            const fileExtension = file.originalname.split('.').pop();
            const fileName = `uploads/${Date.now()}-${file.originalname}`;
            cb(null, fileName);
        }
    }),
    fileFilter: (req, file, cb) => {
        // Allow only specific file types
        const allowedTypes = ['application/pdf', 'image/jpeg', 'image/png', 'image/jpg'];
        if (allowedTypes.includes(file.mimetype)) {
            cb(null, true);
        } else {
            cb(new Error('Invalid file type'), false);
        }
    },
    limits: {
        fileSize: parseInt(process.env.MAX_FILE_SIZE) || 10485760 // 10MB
    }
});

module.exports = upload;

🔒 Security Configuration

7.1 Update RDS Security Group

# Remove public access and restrict to EC2 only aws ec2 revoke-security-group-ingress \ --group-name mindcare-rds-sg \ --protocol tcp \ --port 5432 \ --cidr 0.0.0.0/0 # Add access from EC2 security group only aws ec2 authorize-security-group-ingress \ --group-name mindcare-rds-sg \ --protocol tcp \ --port 5432 \ --source-group mindcare-ec2-sg

7.2 Set Up SSL Certificate (Let's Encrypt)

# Install Certbot sudo apt install -y certbot python3-certbot-nginx # Get SSL certificate sudo certbot --nginx -d your-domain.com -d www.your-domain.com # Set up automatic renewal sudo crontab -e # Add this line: # 0 12 * * * /usr/bin/certbot renew --quiet

7.3 Configure S3 Bucket Policies

Update file uploads bucket policy for secure access:

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "RestrictToApplication",
            "Effect": "Allow",
            "Principal": {
                "AWS": "arn:aws:iam::YOUR_ACCOUNT_ID:user/mindcare-s3-user"
            },
            "Action": [
                "s3:GetObject",
                "s3:PutObject",
                "s3:DeleteObject"
            ],
            "Resource": "arn:aws:s3:::mindcare-file-uploads-yourname/*"
        }
    ]
}

7.4 Update EC2 Security Group

# Remove direct access to Node.js port (now handled by Nginx) aws ec2 revoke-security-group-ingress \ --group-name mindcare-ec2-sg \ --protocol tcp \ --port 5000 \ --cidr 0.0.0.0/0 # Restrict SSH access to your IP only aws ec2 revoke-security-group-ingress \ --group-name mindcare-ec2-sg \ --protocol tcp \ --port 22 \ --cidr 0.0.0.0/0 aws ec2 authorize-security-group-ingress \ --group-name mindcare-ec2-sg \ --protocol tcp \ --port 22 \ --cidr YOUR_IP/32
